# 08 · 风险与平台限制

## 1. 风险清单

按"会不会让产品不可用"排序，不按发生概率排。

| # | 风险 | 影响 | 概率 | 缓解 |
|---|---|---|---|---|
| R-01 | 公司网络客户端隔离，Wi-Fi 与二维码直连都失败 | 公司场景完全不可用 | 高 | BLE 通道必须实现，并在 S2 提前验证 |
| R-02 | 注入在飞书/微信/Electron 里不稳定 | 核心体验打折 | 高 | 三级降级 + 剪贴板兜底；S3 先测再定默认后端 |
| R-03 | Mac 受 MDM 管理，辅助功能被策略锁定 | 功能完全不可用 | 中 | 先确认 Q-01；不可绕过的直接放弃公司场景 |
| R-04 | Secure Input 导致部分 App 无法输入 | 个别场景不可用 | 确定 | 明确不支持，UI 说清楚，不尝试绕过 |
| R-05 | Intel CPU 上识别太慢 | 体验差 | 中 | S1 实测；不行改云端或改虚拟声卡后端 |
| R-06 | 虚拟声卡安装需要管理员权限 + 重启 coreaudiod | B 后端门槛高 | 确定 | B 后端设为可选，不装也能用 A |
| R-07 | 豆包等输入法不显示普通虚拟设备 | B 后端失效 | 中 | S5 验证；必要时按 USB transport 方案改造 |
| R-08 | iOS 18+ 真机无法用 Xcode 15.2 调试 | 手机端无法联调 | 高 | 先确认 Q-03；需要时升 macOS + Xcode |
| R-09 | Android 厂商后台策略杀进程 | 后台收音中断 | 中 | 前台服务 + 电池优化白名单引导；首版接受前台使用 |
| R-10 | BLE 音频积压堵死链路 | 长语音丢失 | 中 | 背压 + 丢帧 + 按键通道独立（S4 验证） |
| R-11 | 剪贴板恢复失败 | 用户剪贴板被覆盖 | 中 | 保存全部类型 + 延迟恢复 + 二次校验 |
| R-12 | 系统升级导致 AX 行为变化 | 注入突然失效 | 低 | 三级降级天然容错；日志里记录 `inject_path` |
| R-13 | Flutter 插件在 BLE/后台录音上能力不足 | 需要大量原生代码 | 中 | 一开始就把 BLE 与录音写成平台通道，不用现成插件兜底 |
| R-14 | 长时间运行内存/CPU 占用升高 | 影响日常使用 | 低 | 模型常驻但空闲不推理；日志滚动 3 天 |

## 2. 平台硬限制（无法绕过，只能接受）

| 限制 | 说明 |
|---|---|
| macOS 不允许第三方 App 自行授予 TCC 权限 | 必须用户手动勾选，只能做引导 |
| Secure Input 期间输入法收不到事件、也无法注入 | 密码框、终端、登录窗一律不支持 |
| iOS 无法模拟 HID 键盘 | 手机不能直接当蓝牙键盘 |
| iOS 后台录音需要 `audio` 后台模式 | 自用可放心用，无审核压力 |
| Android 无 GMS 时系统语音识别不可用 | 本方案识别在 Mac，不受影响 |
| macOS 作为 BLE 外设时系统级绑定支持弱 | 必须做应用层认证 |
| 辅助功能授权与签名绑定 | 换签名/换路径会失效，需固定签名与安装位置 |
| 公司 Wi-Fi 的客户端隔离由网络设备决定 | App 侧无法解决，只能换通道 |

## 4. 明确接受的缺陷

这些不修，写在这里是为了以后不要反复纠结：

1. 密码框不能用。
2. 游戏、远程桌面、部分 Java 应用不能切输入框。
3. 公司网络若连 BLE 都被禁（极少见），就彻底不能用。
4. 识别质量不如豆包输入法（B 后端就是为此保留）。
5. 手机端没有历史记录，只有"最近一条"。
6. 一次最长 60 秒，长内容需要分段说。
